01

Now

The shipped page at 393px, rebuilt from the markup at src/pages-more.ts:44–115 and the cascade that actually lands. Two failures are visible in this frame. The Investment label in the dark band is painted at rgb(17,17,17) on rgb(13,13,13), so it is present for a screen reader and absent for a person. And Essential — the tier Alwin marked popular: true in the data — carries no fill, no border, no shadow and no offset, so it is indistinguishable from Starter, Signature and Social. Both panels in this document use identical tier data; only the CSS differs.

02

Proposed

Same four tiers, same prices, same bullets, same add-ons, same terms, same copy. Three things changed. Essential is inverted black-on-white and carries a white MOST POPULAR flag, so the recommended tier is the only thing on the page that inverts — no colour token, no shadow, no gradient. The dark band's label uses the class the stylesheet already defines. And a hairline-pinned booking bar keeps Book now under the thumb at all times instead of once per card. The spec line that sat unused in config.ts now carries each tier's real duration and location count — it is the fastest way to compare four tiers in ten seconds, and it was already written.

02.A Can four tiers be compared in ten seconds? ✕

Now

No. The popular flag paints nothing, so four cards of identical weight compete equally. Duration is absent entirely — spec is in config.ts and never rendered — so "which session length do I need?" cannot be answered from the card at all.

Proposed

Yes. Price and duration sit on the same horizontal line, above the fold of each card, before any bullet. The inverted card is found in under one second at a glance and skipped thereafter.

02.B Does the dark Investment band land? ✕

Now

Half. The inversion is strong and it does stop the eye, but it introduces the section with a label nobody can read. A band whose first line is invisible reads as an accident, not a decision.

Proposed

Yes. #0a0a0a against 72%-opacity white gives roughly 10:1. The label does its job as a section opener and the band reads as intentional.

02.C Do add-ons and terms bury the CTA? ✕ now → ✓ proposed

Now

On a 393px screen the page is roughly 1,900px tall. The last Book now in the final card sits above six add-on rows and five terms, so it is scroll-past before anyone reaches it.

Proposed

No. Add-ons become a two-column priced list (six rows → three) and the terms sit under a hairline that reads as reference, not as the main act. The pinned bar means the CTA never scrolls away.

02.D Is the CTA repeated and thumb-reachable? ✓

Now

Repeated four times, yes — but the first three are near the top of their own cards and the fourth is deep in the page. All four are cta--sm at roughly 38px, inside the 44px target.

Proposed

Per-tier CTA names the tier ("Book Essential", "Book Starter") so the click carries context, and the pinned bar is a constant 46px target within reach of a right thumb.

03

Proposed at 1280

The same markup at desktop. The tier grid holds all four across the main column so comparison is genuinely parallel — one price row, one spec row, four bullets each, same baseline. The popular card is the only inverted block in the row. Add-ons and terms move into a quiet right rail under a persistent booking CTA, which removes them from the reading path entirely and keeps the left column to exactly one job: choose a package.

04

Changes

Fourteen changes, in the order they should be done. Items 1 and 2 are the two confirmed bugs and are worth doing today; everything after that is design. Effort: S = under 30 min · M = under 2h · L = more.

  1. 01

    Rename eyebrow--inv to invest__label in the markup

    S

    The one-character-class fix. pages-more.ts:86 writes <p class="eyebrow eyebrow--inv">, but .eyebrow--inv has no rule anywhere in the stylesheet, so the base .eyebrow wins and paints var(--ink) — #111 on #0d0d0d. editorial.css:599 already defines .invest__label for exactly this label and it matches nothing in the DOM. Renaming the class in the markup activates the rule that has been sitting there unused. Do not add a new CSS rule — that hides the class-name mismatch instead of fixing it. Expected: roughly 10:1, white at 72%.

    // src/pages-more.ts:86
- <p class="eyebrow eyebrow--inv">Investment</p>
+ <p class="invest__label">Investment</p>
  2. 02

    Give the popular tier a real treatment

    M

    pages-more.ts:58 adds pkg--pop to Essential and nothing binds it: measured computed styles across all four cards are border 0 none, background transparent, shadow none, transform none. Alwin's recommendation is invisible. The treatment is black fill, white text — no new colour token, no shadow, no gradient, and it reads as emphasis in a strictly monochrome system because it is the only inversion in the row. Two supporting details make it scannable without colour: a white MOST POPULAR flag on the card, and Essential moved to first position so the scan starts at the recommendation. Flag the class as load-bearing in a comment the way homeGalleryCount is flagged, so the next edit does not quietly drop it again.

  3. 03

    Render the spec line that is already in the data

    S

    Every tier in config.ts carries a spec string — "30 min · 1 outfit · 1 location" through "90 min · 2–3 outfits · multiple locations" — and servicesPage() never prints it. This is the cheapest real improvement on the page: it turns four text-heavy cards into a duration comparison you can read in one pass, in the site's own uppercase-letterspaced mono layer, and it costs one line of markup.

    // inside card(), after the name
+ <p class="tier__spec">${escapeHtml(t.spec)}</p>
  4. 04

    Move price onto the same line as the tier name

    S

    Price currently sits at the bottom of a card, below five bullets, which means the single most decision-relevant number is the last thing in the block. Name and price on one baseline, spec beneath, fit line beneath that — the decision data lands first, the supporting detail follows. Keeps the desktop price row perfectly parallel across four columns.

  5. 05

    Add a pinned booking bar on mobile

    M

    On a 393px screen the page is roughly 1,900px tall and the last Book now sits above six add-ons and five terms. A hairline-pinned bar keeps a 46px target inside right-thumb reach at all times. It should be white with a 1px solid var(--ink) top rule and slight backdrop blur — no shadow, no colour, no floating pill, which would fight the flush-left layout. Hidden on desktop, where the rail CTA already sits in a fixed position.

  6. 06

    Name the tier in the per-card CTA

    S

    Four identical Book now buttons give the client no idea which one they are committing to. Book Essential / Book Starter carries the context into the click and into the WhatsApp or enquiry-form handoff that follows it. A/B-nothing: this is strictly better copy at the same cost.

  7. 07

    Two-column add-ons with a count in the mono layer

    S

    Six single-column rows become three two-column rows and the add-on block loses roughly half its height. The 6 AVAILABLE meta line comes straight from p.addons.length, so it stays true when Alwin edits the list. Keeps add-ons clearly secondary — useful, not the reason to book.

  8. 08

    Put booking terms behind a hairline, under a count

    S

    Terms are five sentences of legal weight and they are the least valuable thing on the page per pixel. A hairline top rule plus 5 TERMS in the mono layer reframes the block as reference material a client can open, not a wall to scroll past. Content unchanged and still fully visible — nothing is hidden behind an interaction.

  9. 09

    Deepen the Investment band from #0d0d0d to #0a0a0a

    S

    Three points of separation, and it lets the band use the same inverted-black value as the popular card, so the page has one inversion token rather than two. At #0a0a0a the white label clears AA comfortably at 72% opacity. Contrast between the band and the page is what makes it read as a deliberate edge rather than a dark patch.

  10. 10

    Add a one-line range strip under the desktop heading

    S

    4 PACKAGES · R1,200–R3,500 · 50% DEPOSIT TO BOOK · EFT ACCEPTED, hairline-divided, in the mono layer. It answers "is this page for me?" before a single card renders, and it is the one place the deposit mechanic and the Rand range appear outside the band. Derive it from p.tiers rather than typing the numbers, so it cannot drift from the data.

  11. 11

    Give every tier a photograph with object-position

    M

    The card image is the only colour-free emotional signal on the page and it is doing the most work at the smallest size. Keep pictureFor()'s existing sizes and rotate through the gallery as the code does now, but crop with object-position and never object-fit: cover — cover crops faces off, which is fatal in a portrait studio's own portfolio. Per-tier crop points should be hand-picked, and loading="lazy" stays on everything below the first card.

  12. 12

    Move add-ons and terms into a quiet desktop right rail

    M

    At 1280px the main column holds all four tiers in one parallel grid and the supporting material moves to a #fbfbfb rail separated by a single hairline. The left column then does exactly one job. The rail CTA sits at the bottom on margin-top: auto, so it stays at the fold's edge regardless of how many add-ons Alwin adds — the layout does not need revisiting each time the list changes.

  13. 13

    Add a "not sure which package" line above the rail CTA

    S

    "Not sure which package? Send the date and location and Alwin will point at the right one." Four tiers is a real decision and hesitation is the thing that loses the booking. This gives a client who is stuck somewhere to go, so Book now stops being the only exit. It is one line in body grey — not a new component.

  14. 14

    Add a lint gate so orphan classes cannot ship again

    L

    Both bugs on this page are the same bug: a class in the markup with no rule in the stylesheet. .eyebrow--inv is invisible; .pkg--pop is inert. A CI step that extracts class names from the rendered HTML and greps the CSS for each one — flagging both "class in markup, no rule" and "rule in CSS, no element", which is how .invest__label survived — turns a class of invisible defects into a build failure. Worth doing after the twelve design items land, not before.

What this document deliberately does not do

No colour. Emphasis is an inverted black card and nothing else. No accent, no highlight, no tinted "popular" badge — a hue would be the first thing to fight the black-and-white identity and the cheapest thing to regret.

No shadows, no radii, no gradients. Cards are separated by 1px rules and one fill inversion. The popular card is the only corner in the page that differs from flush-left, which is exactly what makes it work.

No change to the mono layer. The uppercase, letterspaced mono treatment is the site's strongest brand decision. Every new element here — spec lines, meta counts, the range strip, the pinned bar — is built inside it rather than beside it.

No new tiers, prices, bullets, add-ons or terms. Everything above renders SITE.pricing as it stands in config.ts. The only content-shaped change is that spec becomes visible.

No object-fit: cover on any photograph. Crop with object-position. This constraint is not negotiable on a photographer's own site.

Items 01 and 02 are the two confirmed bugs. Item 01 is a rename of one class in one line and it turns invisible text into 10:1 text. Item 02 makes Alwin's own recommendation visible. Everything else is craft on top of a page that was already honest.
