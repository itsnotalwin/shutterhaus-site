Contact page — conversion redesign

Everything the site does exists to book Alwin. This is the one page that has to convert, so it is judged as a conversion surface, not a content page: one primary action, placed for the thumb, above the fold, with a real confirmation when it works.

All measurements are the live site at iPhone 16 / iOS 27 / Safari, 393×852, captured in audit-v2/baseline/. Photographs are the real files from public/gallery/. Contact details are the real values from src/config.ts.

Brand constraints held throughout: black & white only, zero saturated colour (including the WhatsApp button, which is a white button on a black panel, not green); mono metadata layer preserved; no object-fit: cover on any photograph; flush-left, hairline rules, heavy display type, brutalist line icons.

The thing I was asked to check first

Good news: SITE.contact.formEndpoint is set, and the mailto dead-end is not reachable. src/config.ts carries formEndpoint: "https://formspree.io/f/xjyklqkp" as a hardcoded string. .env.example contains only VITE_SUPABASE_URL and VITE_SUPABASE_ANON_KEY — there is no form-endpoint key, and no code anywhere reads import.meta.env for one. So wireContact() always takes the Formspree branch and the mailto: fallback below it is dead code. No enquiry is being lost to an empty endpoint.

The real risk is the opposite of the one I was looking for: the endpoint is a hardcoded ID in source rather than config. Any staging, fork or preview build posts into the production inbox, and rotating it is a code change plus a rebuild. That is change 11 — a small fix, not a rewrite.

Change list

Effort: S = under an hour · M = half a day · L = more than a day.

01

Make WhatsApp the primary action, above the form ships first

Today WhatsApp is the fourth line of a grey list below the fold, and the only thing identifying it is the word "WhatsApp" — no number, nothing to recognise at a glance. On a South African mobile audience it is very often the preferred channel over a form: one tap, no typing, no validation, no dropped connection losing a half-written enquiry. The wa.me/27730958363 deep link is already built in contactPage(), so this is markup, not plumbing. Add a prefilled message to the link so a cold tap still lands usefully. B&W, not green — a white button on a black panel.

S
02

Kill the 405 KB photograph on the contact route measured bug

pages-more.ts:179 passes escapeHtml(shot.url) raw — the full 1600×2400 original. aboutPage(), 160 lines above it in the same file, correctly uses bestDerivative() and pictureFor(); the contact figure was simply missed. The derivatives already exist: 49-img-0131-800w.webp is 42 KB, the 400w is 14 KB. One-line fix, and it takes the route from 756 KB to roughly 120 KB. This is the highest ratio of improvement to effort on the whole page.

S
03

Remove object-fit: cover from the contact figure brand rule

Alwin's rule is object-position and focal points, never cover on a photograph. styles.css has .contact__fig img { object-fit: cover } with max-height: 38vh on the parent — so a 2:3 portrait is hard-cropped into a 1.23:1 band and the crop lands wherever the algorithm puts it, not where Alwin framed it. Fix with object-position against a declared focal point, and let the intrinsic ratio drive the box. This one needs Alwin's eye, not mine — he has to say where the subject sits in the frame.

S
04

Give success and failure real, different states measured bug

This is the worst defect on the page and it is not visible in a screenshot. Both outcomes are written into the same <p class="cform__note dim"> — 12px grey, below the fold: "Thanks — got it, I'll reply shortly." and "That didn't send. Email me directly instead." are typographically identical, in the same place. A visitor who cannot tell whether their enquiry went is a lost lead. Swap the form for a confirmation panel, put errors inline against the offending field, and add aria-live="polite" so a screen reader announces the result — there is currently no live region at all, so the confirmation is silent for anyone not looking at that exact line.

M
05

Disable the submit button while the POST is in flight double-submit

wireContact() never disables the button and never sets aria-busy. On a 393px screen the send button is 48px tall and the whole thing is one thumb flick from the bottom edge — a double-tap is easy, and it sends two Formspree POSTs, which means the same enquiry arrives in the inbox twice. form.reset() only runs on success, so the button is live for the entire round trip. Set disabled on the first tick, restore it in a finally, and label the in-flight state so the tap has visible feedback.

S
06

Drop the "What do you need?" select noise

It is not required, it has no empty state, and its first option — "Mini session" — is pre-selected, so a visitor who ignores it still silently books a mini session into Alwin's triage. It costs 44px of an 852px viewport and renders as a native iOS picker wheel, the one control on the page that ignores the hairline brutalist system entirely. The free-text message already carries this. Fold it into the placeholder: "Date, location, what you're after…". If Alwin genuinely triages on it, replace it with a 3-up row of hairline chip radios — same data, one tap instead of a wheel.

S
07

Shorten the heading; move the service copy to /services

"Let's Create Something Beautiful." occupies 127–213px of an 852px viewport — 25% of the fold — and promises rather than instructs. "Tell me what you're shooting." is the same voice, two lines instead of three, and asks the visitor for the one thing that starts a booking. The blurb's "…full galleries and prints available on request" is a /services sentence; that page already owns it. Together: ~90px returned to the fold, spent on the action.

S
08

State the reply time next to the action ships first

"Evenings & weekends, by appointment" is the last line on the page and reads as a deterrent: someone who is told a photographer is hard to reach, takes that as an answer and leaves. It is also the best filter Alwin has — he genuinely does not shoot weekdays. Keep the line, move it up beside the button, and pair it with "replies within a day" so the constraint reads as reliability instead of distance. Cheap copy, real effect on the only decision this page asks for.

S
09

Pull the contact details up; stop burying the number twice ships first

The list starts around 1100px — 250px below the fold, so on load the page contains no way to contact Alwin at all. In the proposed order it starts at ~700px. Order it location, email, phone, Instagram — the number already appears twice above it, in display type and on the button, so the list line becomes confirmation rather than the only source.

S
10

Decide what the photograph is actually for

It is photos[0] — the same frame the portfolio opens with, since demo.ts sorts by album. On a page whose only job is conversion it is a picture of a stranger that proves nothing, carrying 54% of the weight. Proposed: drop it on mobile, keep it on desktop where it fills a column the eye expects to be full. If a human face belongs on this page, it should be Alwin's, not a client's — aboutPage() already looks for a marked photographer frame, so the data to do this properly may already be there. This is a judgement call and Alwin should make it; the mockup shows the split so both answers are visible.

M
11

Move the Formspree ID out of source and into config ships first

The endpoint is not empty — it is https://formspree.io/f/xjyklqkp, hardcoded in config.ts, and the mailto: dead-end is unreachable. So the failure I was asked to check for is not happening. The exposure is the inverse: a hardcoded ID means any staging, fork or preview build posts into the production inbox, and rotating it is a code change plus a rebuild. .env.example has no key for it and nothing reads import.meta.env for one. Add VITE_FORMSPREE_ENDPOINT, default to the current value so nothing breaks, and add the key to .env.example with an empty value. (Keys present/absent only — no values printed.)

S
12

brokenImgs: 1 in the baseline is a false positive — fix the audit, not the page

tools/audit2-baseline.mjs:102 counts imgs.filter(i => i.complete && i.naturalWidth === 0). The lightbox is mounted site-wide with an <img class="lb__img" alt=""> that has no src until a photo is opened — an empty image is complete === true with naturalWidth === 0, so it matches the broken filter on every route. The contact page's 2 images are that phantom plus the real figure. Exclude img:not([src]) and [data-lb] from the probe, otherwise this metric will keep crying wolf and a real break will be ignored. Not a page defect — the photographs are all fine.

S
13

Give the form a no-JS fallback so it is never a dead control

The form is novalidate, has no action and no method, and its only handler is JS. If the script fails to parse or a CDN hiccups, submitting it does a GET back to the current page and silently discards everything typed. Setting action="https://formspree.io/f/xjyklqkp" method="POST" costs nothing — JS still intercepts for the nicer states, and the raw POST works if it never loads. Same reasoning as change 11; both should land together.
